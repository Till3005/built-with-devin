ガイド 19 — セッションの全ループ：リサーチ、委任、レビュー、そしてコスト

目標： Devin の全ループを端から端まで回す——ブリーフを書く前にインデックスでコードベースを理解し、スコープされたセッションを委任し、独立レビューを PR に通し、Session Insights を読んで次のループを安くする。 レベル： 入門（ガイド 18 とペア） 出典： Devin University — Cloud 101/103 · DeepWiki ドキュメント · Ask Devin ドキュメント · Devin Review ドキュメント · Session Insights ドキュメント

大半の人が半分しか回さないループ#

ガイド 18 は Devin が誤読しないブリーフの書き方を教えた。Devin University の Cloud トラックは、そのブリーフを生み出し、その成果を消費する完全なループで包む：

理解 ──► 委任 ──► レビュー ──► 学習
 DeepWiki    ブリーフ+      Devin Review   Session Insights
 Ask Devin   セッション      PR 上で        → 次のブリーフ改善

失敗するセッションのほとんどは、真ん中ではなく両端で死ぬ：コードベースを知らずにブリーフを書いたか、雰囲気で PR をマージしたかだ。このガイドは両端と、その下を走るメーターを扱う。

理解：最初の ACU を使う前に DeepWiki と Ask Devin#

DeepWiki は接続されたリポジトリを自動でインデックスし、リポジトリごとに wiki を生成する——アーキテクチャ図、要約、ソースリンク。.devin/wiki.json で設定可能。セッション時間を使って発見していた質問——このモジュールはどこか、何が呼んでいるか、確立されたパターンは何か——に先回りして答える。

  • エフォートレベルは組織単位で設定（リポジトリごとに上書き可能）：Low は無料でデフォルト。Medium は wiki あたり約 5–10 ACU、High は約 20–40。ブリーフ支援なら多くのリポジトリで Low で十分。
  • オンボーディングで設定したリポジトリは自動でインデックスされる。残りは Settings → DeepWiki から追加。
  • 公開リポジトリには無料版 deepwiki.com がある——任意の公開 GitHub リポジトリをインデックスし、同じ図と Q&A をアカウントなしで得られる。他のエージェント向けの DeepWiki MCP もある。

Ask Devin はそのインデックスの上の会話レイヤー——app.devin.ai/search で：

  • Ask モード：コードについての質問に、インデックスに基づくコード引用つきで回答——「billing poller のリトライはどう動くか」にファイル、呼び出し箇所、パターンが返る。
  • Plan モード：変更を説明すると Devin が一緒にスコープを決め——セッションに渡せるコンテキスト豊富なプロンプトを生成する。ガイド 18 のルールを満たす最も安い方法：どこから始めるか、どのパターンを参照するかは、記憶ではなくインデックスから来る。
  • 会話の中からセッションを開始でき、ステータスもその中に残る——コンテキストスイッチ不要。

リターンは二重だ：インデックスの事実で書かれたブリーフは、より具体的かつ短くなる。

委任——もう知っているステップ#

Ask Devin が生成したプロンプト（またはガイド 18 通りに書いたブリーフ）をスコープされたセッションとして渡す。変わるのは、ブリーフがすべてを知っていることだけ：ファイル、パターン、検証チェック、境界。

レビュー：すべての PR に第二のエージェント#

Devin Review は独立したレビュアーであり、セッションの自己評価の再演ではない：

  • PR 単位のトリガー：GitHub PR や GitLab MR に /devin review とコメントするか、Devin Review で PR を開く。関連する変更をグループ化し、diff に沿って説明し、チャットに引用できるバグやセキュリティの所見を提示——Devin にその場で修正させることもできる。
  • 組織全体：自動レビュー、レビュー指示、コスト管理があり、全 PR で実行できる。Review 2.0（2026年11月）で PR あたりのコストが 82% 削減され——常時稼働が経済的に成立するようになった。
  • Devin 自身の PR にも使う。書き手とレビュアーが別のエージェントであることが要点——ガイド 18 があなたに割り当てる非対称と同じだ。

学習：Session Insights と ACU メーター#

完了したすべてのセッションに Session Insights がつく（メニュー ⋯ → Session insights、無料）：

  • セッションサイズチップ——XS–XL の自動分類がティアダウン時に生成。L/XL セッションは自動で完全分析、小さいものは手動トリガー。
  • ACU 使用量（クォータ制プランではオンデマンドのドル表示）——類似タスクを比較して、リトライや袋小路に計算資源を燃やしたセッションを見つける。
  • ユーザーメッセージ数——多いのはブリーフのコンテキスト不足のサイン。各メッセージは冒頭で書けたはずの軌道修正。
  • 分析は具体的な改善を勧める——より厳密なプロンプト、不足している knowledge、誤ったスコープ。Cloud 103 の目標が正しい：毎回のセッションを前回より安く。

すべてのフィールドレポートに登場するコスト規律：セッションのスコープを狭く、放置セッションは止める（思考も待機も課金される）、フリートを回す前にクォータを確認——100 Days の運営者は Bot セットアップの 2 日間で週間クォータの 33% を燃やした（フィールドレポート）。Bots 固有の注意点としてコミュニティで報告された件：Bot の子セッションに自分のモデルキーを接続しても、プランの週間クォータの消耗は止まらない——Bot 本体の推論とクラウドコンピュートは引き続きプランに課金される（linux.do レポート、zh）。

確認リスト#

落とし穴#

  • 目隠しブリーフ。 数ヶ月開いていないコードベースの記憶でプロンプトを書く——今はインデックスの方が詳しい。Ask Devin の 2 分はセッション途中の修正に勝る。
  • CI が緑だからレビューを飛ばす。 CI が検査するのは思いついたチェックだけ。Review は diff そのものを読む。網が違う。
  • 失敗時だけ Insights を読む。 高いのは毎週繰り返す平凡なセッション。成功もレビューせよ——再利用できるブリーフはそこにある。
  • エフォートレベルの過剰。 四半期に一度しか触らないリポジトリに High レベルの wiki。リポジトリ別上書きはそのためにある。

理解度チェック#

  1. なぜ Devin サイドバーではなく Ask Devin からセッションを始めるのか？ Plan モードがプロンプトをインデックス済みコードに根づかせるから——どこから始めるか、既存パターン、検証可能な面はすべてリポジトリ自身から来るので、セッションは手で打つか途中で発見するはずのコンテキストを持って始まる。
  2. セッション自身の報告が完了・テスト済みと言っているのに、なぜ Devin Review を回すのか？ 独立性。セッションは自分の宿題を採点した。Review は別のエージェントが新鮮なコンテキストで diff を読む——チームメイトの PR を自己承認しないのと同じ理由。
  3. ACU は定額で、あるセッションが XL になった。最初に何を見るか？ Session Insights のユーザーメッセージ数——多数の小さな修正に駆動された大きなセッションはブリーフの問題であり、タスクサイズの問題ではない。作業が本当に大きかったと結論する前に、分割か再ブリーフを。
