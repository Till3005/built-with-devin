ガイド 8 — デザインとビジュアルワーク

目標： Devin をアートディレクター兼実装者として使い、本番のビジュアルデザイン——生成画像、アニメーションシステム、タイポグラフィ——を会話だけで作る。 レベル： 中級 出典となる導入事例： Spraycash ランディングページ——フィンテックサイトの全ビジュアルシステムを Devin チャット内で Kimi K3 と設計、全プロンプト公開：ヒーロー画像、レイヤードクラウドアニメーション、SVG 描画リング、3 フォントタイプシステム。 出典： 全プロンプト付き記事

パターン

エージェント経由のデザインは、プロンプトが雰囲気を記述するとき失敗する（「プレミアム感で」）。デザイナーにブリーフするようにアートディレクションすると機能する：参照、制約、批評ループ。デザインツールに対する Devin の優位は実装を産むこと——アニメーションはコード、画像は生成されて配置され、タイプシステムは出荷される CSS。

ブリーフ + 参照 ──► Devin がビジュアルアセット + コードを生成
        ▲                     │
        └──── 批評ループ：「リングのアニメーションが速すぎる、
              stroke-dashoffset のイージングを 1.4s に遅く」─────┘

ステップ 1 — クリエイティブディレクターのようにブリーフする

Spraycash 記事のプロンプトは一つの形を共有——具体的な名詞、趣味の形容詞なし：

Hero section: dark navy (#0A1628) background, a circular progress ring
as the visual anchor — SVG stroke-dashoffset draw-on animation over
1.4s ease-out, layered clouds behind it drifting on separate
translateX loops at 40s/60s/90s periods so the parallax never repeats.

与えるもの：パレットの hex 値、アニメーションの機構（「動かして」ではない）、タイミング値、レイヤー順。

ステップ 2 — ピクセルの前にタイプシステムを固める

Spraycash はコンポーネントに触る前に 3 フォントシステム——ディスプレイ、本文、モノ——を早期に固定した。同じことをする；これが単独で最もレバレッジの高い視覚決定：

Type system: <display font> for hero + section heads, <body font> for
prose, <mono> for numbers/labels. Set the scale: 64/40/28/18/14.
Nothing else uses another size.

ステップ 3 — セッション内で画像を生成する

Devin はアセットを生成して配置する——デザインされたページにストックフォトを貼るな。記事はブリーフのパレットに合わせた生成ヒーロー画像を示す。スタイル指示（パレット、照明、材質）を一度固定し、すべてのアセット要求で再利用すれば、生成アセットの一貫性が保てる。

ステップ 4 — 形容詞ではなく機構でアニメーションする

曖昧（失敗） 機械的（成功）
「なめらかな入場」 "stagger children 80ms, translateY(12px)→0, opacity 0→1, 400ms ease-out"
「さりげないパララックス」 "three layers, translateX loops at 40/60/90s periods"
「リングを描画」 "stroke-dasharray = circumference, animate dashoffset C→0 over 1.4s"

Spraycash のリング、雲、段階的出現はすべてこのレベルで指定された——そしてモックではなく実際の CSS/SVG として出荷された。

ステップ 5 — 批評ループこそがクラフト

記事の本当の教訓：品質は反復から来た——「リングの描画が速すぎる」「雲がノイズに見える、不透明度 30% 下げ」「数字にモノフォント」。視覚的アンカーごとに 3〜5 回の批評ラウンドを見積もる。Devin はページ全体をコンテキストに保持する；各ラウンドはチケットではなくメッセージ一つ。

検証チェックリスト

  • [ ] ページがストック画像ゼロでレンダリングされる——全アセットが生成かコード
  • [ ] すべてのアニメーションが CSS 内にタイミング値を持つ名前付き機構
  • [ ] タイプシステム 1 つ、スケール 1 つ——迷子のサイズなし
  • [ ] 3 つ以上の幅で確認し、破損やクリップなし

落とし穴

  • 形容詞プロンプト。 「プレミアム」「洗練」「モダン」はスロップを生む。機構と値がクラフトを生む。
  • 一発撮り。 最初のレンダーを受け入れるからエージェント製ページがエージェント製に見える。品質は批評ループに住む。
  • 固定化の欠落。 パレット + タイプシステムを先に制約として設定；制約設定前に生成されたアセットは後から決して合わない。

理解度チェック

  1. なぜ Spraycash の著者は全プロンプトを原文で公開したか？（プロンプト列こそがデザイン成果物——会話によるアートディレクションは、会話が再現可能なときだけ再現可能）
  2. 「生成画像 + レイヤードアニメーション」に必要で、スクリーンショットのモックにないものは？（出荷可能なアセットと動作するアニメーションシステム——検証は画像ではなくレンダリングされたページ）
  3. ランディングページでデザインツールよりチャット指示が優れるのはいつか？（出力がどうせ本番コードになるとき——デザインセッションこそが実装）
